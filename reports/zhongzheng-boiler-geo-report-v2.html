Generative Engine Optimization Audit

中正锅炉 GEO 诊断报告 V2

基于奥卡姆剃刀与第一性原理重做：不追求看起来复杂的分数体系，先解决 AI 搜索引用一个页面所需的三件事：能抓到、能读懂、能信任。

生成日期：2026-08-17 主对象：中正锅炉官网与产品中心 输出：可执行 GEO 修复报告

一句话结论

中正锅炉已经具备较强的产品事实基础，尤其是 zozen.com 产品页有型号、容量、压力、燃料、行业和参数表；当前 GEO 最大短板不是“没有内容”，而是官方入口一致性、发现入口、结构化表达和问答型答案素材还没有形成稳定闭环。

1. 结论与优先级

本版报告采用风险等级，而非未经披露规则的精确分数。核心判断来自可观察页面、浏览器抽样、原始报告和复审报告。

高风险 官方入口不一致

原报告重点审计 zzgl.cn；本次观察到 zozen.com 产品中心可访问且内容更完整，zzgl.cn 仍出现超时。

高风险 发现入口不足

zozen.com/sitemap.xml 返回页面不存在的 HTML；robots.txt 本次被浏览器客户端拦截，需服务器侧复核。

中风险 答案素材未聚合

产品详情页有参数表，但产品中心缺统一对比表、采购 FAQ、来源与更新时间聚合层。

中风险 结构化数据缺失

首页、产品中心和抽样产品详情页均未观察到 JSON-LD；schema 应在可见事实补齐后再上。

立刻做的三件事

P0

确定唯一官方主入口与域名策略

如果中正锅炉当前主站是 zozen.com，应明确 zzgl.cn 的角色：301 到对应页面、保留镜像、或彻底从公开报告中移除。AI 搜索和传统搜索都需要稳定的实体入口，多个入口状态不一致会削弱候选构建和引用信心。

P0

修复 sitemap 与抓取复测链路

sitemap.xml 不应返回 404 型 HTML 页面。先用服务器日志、Search Console、外部无 Cookie 请求确认 Googlebot、Bingbot、主流 AI 抓取器和普通浏览器是否能稳定访问首页、产品中心、产品详情页、robots.txt 与 sitemap。

P1

把已有产品事实做成“采购答案层”

现有详情页已经有 WNS、DZL、YQL 等参数表，不必推倒重来。最小改造是在产品中心增加统一字段表和 8-12 个选型 FAQ，让 AI 可以直接回答“产品有哪些、怎么选、哪个更适合”。

5. 技术实现建议

P0

域名与 canonical 治理

首页、产品中心、详情页都应有稳定 canonical。若 zzgl.cn 不再作为主入口，应 301 到 zozen.com 对应页面；若保留，则两端内容、canonical、sitemap、robots 策略要一致。

P0

sitemap 与 robots

sitemap.xml 应返回 XML，包含首页、产品分类页、产品详情页、行业方案页、FAQ 页、案例页，并包含 lastmod。robots.txt 应明确 Sitemap 地址，并避免阻断核心页面。

P1

页面标题层级

首页当前未观察到 H1，产品中心 H1 为“产品”过泛。建议首页 H1 明确为“中正锅炉”，产品中心 H1 改为“中正锅炉产品中心”，并减少重复“产品中心”标题。

P1

结构化数据

先补 Organization、WebSite、WebPage、BreadcrumbList；详情页再补 Product。FAQPage 只标记页面可见 FAQ，不标记隐藏或不存在的问题。Google 文档也强调结构化数据必须代表页面主内容、不能标记用户不可见内容。

schema 的顺序原则：先让正文可信，再让机器读懂。不要把未在页面可见正文出现的价格、资质、销量、认证、案例或效率写进 JSON-LD。 

{
  "@context": "https://schema.org",
  "@type": "Organization",
  "name": "无锡中正锅炉有限公司",
  "alternateName": "中正锅炉",
  "url": "https://www.zozen.com/",
  "telephone": "400-161-0099",
  "email": "info@zozen.com",
  "address": {
    "@type": "PostalAddress",
    "addressRegion": "江苏省",
    "addressLocality": "无锡市宜兴市",
    "streetAddress": "周铁镇新达路76号"
  }
}
